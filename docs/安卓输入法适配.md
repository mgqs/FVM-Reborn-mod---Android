# 安卓输入法（软键盘）适配 —— SearchBox

> 本文记录的是**嫁接段**（上游没有、只有安卓版有），同步上游时务必保住。
> 涉及文件：`objects/SearchBox/Create_0.gml`（`focus()` / `blur()` / `on_step()` 的 `os_type == os_android` 分支）

## 现象（2026-11-08）

情报岛 / 授权页 / 商店凭证页的搜索框，点一下系统软键盘**正常弹出**，但敲什么都没有反应：
英文、数字、中文拼音全都不上屏，退格也没用。

## 根因

`on_step()` 尾部有一行**每帧执行**的回写：

```gml
keyboard_string = self.state.text
```

桌面端这行是必须的（把本框文字写回键盘缓冲，下一帧才有比对基准）。安卓上它是致命的：

- 安卓的输入法（IME）通过系统 `EditText` 维护自己的缓冲，`keyboard_string` 是它对 GML 的投影。
- 每帧回写 = 每帧对输入法 `setText()` 一次。中文输入法的**组合态**（拼音还没上屏那一段）
  每帧被冲掉，一个字母都提交不了；英文/数字在部分机型上也会因为光标被复位而全丢。
- 所以键盘能弹、光标会闪，但框里永远是空的。

对照组：`objects/obj_material_sell_confirm/Step_0.gml` 只在**内容真的变了**时才写
`keyboard_string`，那个数量输入框在安卓上一直是好的 —— 差别就在「每帧写」和「按需写」。

## 修法

安卓分支彻底**只读不写**：把 `keyboard_string` 当成唯一缓冲，只跟上一帧副本 `kb_prev` 比对，
把「变的那一段」吸收进 `self.state.text`：

| 情况 | 处理 |
|---|---|
| 缓冲变长且以旧串为前缀 | 多出来的那段插到光标处（正常打字 / 中文上屏） |
| 缓冲变短且是新串以旧串为前缀 | 删光标前一个字（输入法退格） |
| 变成空串而框里有字 | 认为是刚弹键盘时输入法清空缓冲 → **重新播种**，不当作退格 |
| 其他变化（组合态等判定不了） | 整串接管，光标跟到末尾 |
| 缓冲没变但按了 `vk_backspace` | 按「删光标前一个字」处理（个别输入法只发按键） |

尾部回写加了平台守卫：

```gml
if (os_type != os_android) {
    keyboard_string = self.state.text
    self.state.kb_prev   = keyboard_string
}
```

另外修了一个焦点接力问题：`blur()` 原本无条件 `keyboard_virtual_hide()`。
同一个画面里存在多个输入框时（情报岛 + 授权/凭证），点另一个框会让两个实例的 Step 都跑，
「先 focus 再 blur」会把刚弹起来的键盘又收掉。现在 `blur()` 先问
`searchbox_any_focused(id)`，有别的框已经接手焦点就不收键盘。

## 同步上游时要注意

上游（`FVM-Reborn-mod`）对 `objects/SearchBox/Create_0.gml` 的改动是**光标插中间**那套逻辑
（`caret` / `kb_prev` / 每帧回写）。三方合并时：

1. `caret` / `kb_prev` 字段、`insert_at_caret()`、`set_caret_from_mouse()` **全部保留**（上游的）。
2. `on_step()` 的输入段要**整段换成**「安卓分支（只读）+ 桌面分支（原有）」的双路结构。
3. 尾部回写必须留在 `if (os_type != os_android)` 里 —— 这是整次修复的核心，最容易在合并时丢掉。
4. 用 `.codex-tmp/brace_check.py` 之类先验括号配平：这段嵌套深，漏一个 `}` 会在事件末尾报
   `got '' expected '}'`。
